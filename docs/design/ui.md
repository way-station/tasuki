# UI design basics: colors, typography, spacing

- Status: Draft
- Issue: #146
- Related: `docs/design/ui-references.md` (#145), `docs/design/screens.md`, ADR-0007 (LINE Login), ADR-0012 (frontend structure)

This document decides the colors, typography, spacing, and the shape of lists for every MVP screen. `docs/design/screens.md` decides what each screen shows, and `docs/design/ui-references.md` which shipped app each screen's structure comes from. Common components (#147) and wireframes (#148) are decided separately.

## How the values were chosen

`docs/design/ui-references.md` does not start from designs generated by AI tools, so that every choice has a reason that can be checked later. In the same spirit, every value here comes from an outside standard, named next to it:

- Colors: the default palette of Tailwind CSS, which the frontend already uses (#33), keeping only the shades whose text contrast meets WCAG 2.2 (4.5:1 or more for text).
- Typography: the text styles of Apple's Human Interface Guidelines (Dynamic Type, default size).
- Spacing and sizes: Tailwind's 4 px scale, and touch targets of at least 44 px from the Human Interface Guidelines.
- Lists: one card per item, as Material Design 3 lays out lists of cards.

Three options were compared on 2026-11-15 (iOS-like, Material-like, and one built on Tailwind's defaults). The chosen mix is the Tailwind-based option for colors and spacing, the Material-like option for the shape of lists, and the iOS-like option for typography.

## Language

Screen text is Japanese for now. The MVP has no language switching.

## Colors

| Use | Tailwind | Value | Contrast |
| --- | --- | --- | --- |
| Page background | `slate-50` | `#F8FAFC` | — |
| Card and header background | `white` | `#FFFFFF` | — |
| Lines and card borders | `slate-200` | `#E2E8F0` | — |
| Borders of inputs, choices, and secondary buttons | `slate-500` | `#64748B` | 4.8:1 on white (WCAG 2.2 asks 3:1 for the edges of controls) |
| Text | `slate-900` | `#0F172A` | 17.1:1 on `slate-50` |
| Secondary text | `slate-600` | `#475569` | 7.6:1 on white, 7.2:1 on `slate-50` |
| Accent: links, the selected choice, main buttons | `blue-700` | `#1D4ED8` | 6.7:1 on white; white text on it 6.7:1 |
| Selected background | `blue-100` | `#DBEAFE` | `blue-700` text on it 5.5:1 |

States are shown as labels. Each pair differs in lightness as well as hue, so they can be told apart without color.

| State | Text | Background | Contrast |
| --- | --- | --- | --- |
| Running order confirmed | `green-800` `#166534` | `green-100` `#DCFCE7` | 6.5:1 |
| Not answered, waiting for approval, warnings | `amber-800` `#92400E` | `amber-100` `#FEF3C7` | 6.4:1 |
| Undecided (保留), draft, empty leg (未定), left, no user | `slate-700` `#334155` | `slate-100` `#F1F5F9` | 9.5:1 |
| Error | `red-700` `#B91C1C` | `white` with a `red-700` border | 6.5:1 |

- The LINE Login button keeps the colors, shape, and wording the LINE Login button guidelines require (ADR-0007). LINE green is used for that button only, so it is never mistaken for one of tasuki's own buttons.
- Not used: iOS's default blue `#007AFF` (4.0:1 on white, below 4.5:1 for body text) and lighter shades of the palette for text.

## Typography

Sizes and line heights are the Human Interface Guidelines' text styles at the default size, in CSS px.

| Style | Size / line height | Weight | Used for |
| --- | --- | --- | --- |
| Large Title | 34 / 41 | Bold | The title of a top screen (R1 and the other home screens) |
| Title 1 | 28 / 34 | Bold | The title of a detail screen (for example the race name on R2) |
| Title 2 | 22 / 28 | Bold | Large numbers (for example the average time on P1) |
| Headline | 17 / 22 | Semibold | Card titles, emphasized text |
| Body | 17 / 22 | Regular | Body text, inputs, buttons |
| Subheadline | 15 / 20 | Regular | Second lines (dates, distances) |
| Footnote | 13 / 18 | Regular | Group headings, notes, state labels |

- The Human Interface Guidelines use Regular for the titles. tasuki uses Bold for them, as in the compared designs, so Japanese titles stand out from the body text.
- Text smaller than 13 px (Caption 1 and 2) is not used.
- Font: `"Hiragino Sans", "Hiragino Kaku Gothic ProN"` first, then Tailwind's default `font-sans` (`ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji"`). iPhones show Hiragino; Android has no Hiragino and shows its own system font through `font-sans`.

## Spacing and sizes

- Tailwind's 4 px scale (`1` = 4 px). Steps used: 4, 8, 12, 16, 24 px (`1`, `2`, `3`, `4`, `6`).
- The left and right margin of a screen is 16 px (`px-4`).
- Anything that can be tapped is at least 44 px high (`min-h-11`).
- Corners: cards 12 px (`rounded-xl`); inputs, buttons, and choices 8 px (`rounded-lg`); state labels fully round (`rounded-full`).

## Lists

- A list is a column of cards, 8 px apart (`gap-2`), not rows inside one box.
- A card: white background, `slate-200` border, 12 px corners, at least 72 px high, 12 px padding above and below and 16 px at the sides.
- Inside a card: the title (Headline) and a second line (Subheadline, secondary text) on the left; a state label, if any, on the right.
- Lists are grouped under headings in Footnote and secondary text (for example "参加する大会" and "招待" on R1).

## Wireframes

The wireframes of every MVP screen (#148) are in [`docs/design/wireframes/`](wireframes/index.html). Open `index.html` in a browser. They use the values of this document through `wireframes.css`. The common components (#147) are in [`docs/design/components.md`](components.md).

## Putting it in the frontend

The values go into the `@theme` block of `app/frontend/src/index.css` (#33) when the screens are built, in the UI issues of each feature. This document does not change the code.

## Not decided here

- Dark mode.

# UI のデザインの基本：色・文字・余白

- Status: Draft
- Issue: #146
- Related: `docs/design/ui-references.md`（#145）、`docs/design/screens.md`、ADR-0007（LINE ログイン）、ADR-0012（frontend の構成）

この文書は、MVP のすべての画面の色、文字、余白、一覧の形を決める。各画面に何を出すかは `docs/design/screens.md` が決め、各画面の構成をどの公開済みのアプリから取るかは `docs/design/ui-references.md` が決める。共通の部品（#147）とワイヤーフレーム（#148）は別に決める。

## 値の選び方

`docs/design/ui-references.md` は、あとから理由を確かめられるように、AI のツールで作ったデザインから始めない。同じ考えで、ここの値はどれも外の基準から取り、その基準を隣に書く。

- 色：frontend がすでに使っている Tailwind CSS（#33）の既定の色から、文字のコントラストが WCAG 2.2 を満たす（文字は 4.5:1 以上）段階だけを使う
- 文字：Apple の Human Interface Guidelines の文字の段階（Dynamic Type、標準の大きさ）
- 余白と大きさ：Tailwind の 4 px の目盛りと、Human Interface Guidelines の「押せるところは 44 px 以上」
- 一覧：Material Design 3 のカードの一覧のように、1 件ずつカードにする

2026-11-15 に 3 つの案（iOS 寄り、Material 寄り、Tailwind の既定値をもとにした中間）を比べた。色と余白は中間の案、一覧の形は Material 寄りの案、文字は iOS 寄りの案を採った。

## 画面の言葉

画面の文言は、ひとまず日本語にする。MVP では言語を切り替えられない。

## 色

| 使い道 | Tailwind | 値 | コントラスト |
| --- | --- | --- | --- |
| 画面の背景 | `slate-50` | `#F8FAFC` | — |
| カードとヘッダーの背景 | `white` | `#FFFFFF` | — |
| 線とカードの枠 | `slate-200` | `#E2E8F0` | — |
| 入力、選択肢、2 番目のボタンの枠 | `slate-500` | `#64748B` | 白の上で 4.8:1（WCAG 2.2 は操作できる部品の縁に 3:1 を求める） |
| 文字 | `slate-900` | `#0F172A` | `slate-50` の上で 17.1:1 |
| 補足の文字 | `slate-600` | `#475569` | 白の上で 7.6:1、`slate-50` の上で 7.2:1 |
| 強調：リンク、選んでいる選択肢、主なボタン | `blue-700` | `#1D4ED8` | 白の上で 6.7:1。その上の白い文字も 6.7:1 |
| 選んでいるものの背景 | `blue-100` | `#DBEAFE` | その上の `blue-700` の文字は 5.5:1 |

状態はラベルで示す。どの組み合わせも、色合いだけでなく明るさも変えているので、色が見分けにくい人にも区別できる。

| 状態 | 文字 | 背景 | コントラスト |
| --- | --- | --- | --- |
| 走順確定 | `green-800` `#166534` | `green-100` `#DCFCE7` | 6.5:1 |
| 未回答、承認待ち、注意 | `amber-800` `#92400E` | `amber-100` `#FEF3C7` | 6.4:1 |
| 保留、下書き、空きの区（未定）、退会、ユーザーなし | `slate-700` `#334155` | `slate-100` `#F1F5F9` | 9.5:1 |
| エラー | `red-700` `#B91C1C` | `white`、`red-700` の枠 | 6.5:1 |

- LINE ログインのボタンは、LINE ログインボタンのデザインガイドラインが決める色、形、文言のままにする（ADR-0007）。LINE の緑はそのボタンだけに使い、tasuki のボタンと取り違えないようにする
- 使わないもの：iOS の既定の青 `#007AFF`（白の上で 4.0:1 で、本文の 4.5:1 に届かない）、文字に使う薄い段階の色

## 文字

大きさと行の高さは、Human Interface Guidelines の文字の段階の標準の大きさを、CSS の px にしたもの。

| 段階 | 大きさ / 行の高さ | 太さ | 使い道 |
| --- | --- | --- | --- |
| Large Title | 34 / 41 | Bold | 最初の画面の題（R1 などのホームの画面） |
| Title 1 | 28 / 34 | Bold | 詳細の画面の題（たとえば R2 の大会名） |
| Title 2 | 22 / 28 | Bold | 大きく見せる数字（たとえば P1 の平均タイム） |
| Headline | 17 / 22 | Semibold | カードの題、強調する文字 |
| Body | 17 / 22 | Regular | 本文、入力、ボタン |
| Subheadline | 15 / 20 | Regular | 2 行目（日付、距離） |
| Footnote | 13 / 18 | Regular | グループの見出し、補足、状態のラベル |

- Human Interface Guidelines は題を Regular にしている。tasuki では、比べた案のとおり題を Bold にして、日本語の題が本文から目立つようにする
- 13 px より小さい文字（Caption 1 と 2）は使わない
- 書体：まず `"Hiragino Sans", "Hiragino Kaku Gothic ProN"`、そのあとに Tailwind の既定の `font-sans`（`ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji"`）。iPhone ではヒラギノになる。Android にはヒラギノがないので、`font-sans` を通して端末の書体になる

## 余白と大きさ

- Tailwind の 4 px の目盛り（`1` = 4 px）。使う段階は 4、8、12、16、24 px（`1`、`2`、`3`、`4`、`6`）
- 画面の左右の余白は 16 px（`px-4`）
- 押せるものは、高さ 44 px 以上（`min-h-11`）
- 角丸：カードは 12 px（`rounded-xl`）。入力、ボタン、選択肢は 8 px（`rounded-lg`）。状態のラベルは丸（`rounded-full`）

## 一覧

- 一覧は、1 つの箱の中の行ではなく、8 px ずつ離したカードの列にする（`gap-2`）
- カード：白い背景、`slate-200` の枠、角丸 12 px、高さ 72 px 以上、上下 12 px・左右 16 px の内側の余白
- カードの中：左に題（Headline）と 2 行目（Subheadline、補足の文字）、右に状態のラベル（あるとき）
- 一覧は、Footnote・補足の文字の見出しでまとめる（たとえば R1 の「参加する大会」と「招待」）
